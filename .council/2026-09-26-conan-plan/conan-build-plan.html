Build plan · 24-hour hackathon · supersedes the ClauseGuard roadmap

Conan: from clauses to consequences

Conan turns a contract PDF into a source-linked set of obligations, links them in a dependency graph, and flags explainable, attention-priority risk. It also shows when a blocked upstream duty puts downstream ones at risk. This plan is the output of a four-model engineering council.

§1Summary

The LLM reads the language. Code does everything that needs to be exactly right: pages, IDs, dates, graph checks and risk. Every number on screen traces back to a visible factor or a user action.

Four rules we never cut

  1. The LLM never outputs page numbers or IDs. The page is wherever the verified evidence quote sits in the PDF's text, so it is correct by construction.
  2. No invented dates. Every due date comes from a date written in the contract, a date the user entered, or a user marking an obligation done. A property test enforces this.
  3. Risk is the sum of visible factors. Scores are additive capped points labelled "attention priority, not probability of breach". Explanations are templates, never LLM prose.
  4. Fallbacks are honest. Cached, sample and offline data always carry a visible label.

What ships

  • MVP: upload, clauses, obligations, human review, filters, source links, timeline, graph, risk breakdown
  • D1: dependency risk propagation, with evidence shown on every edge
  • D2: deterministic clause-conflict flags
  • Stretch: ICS/CSV export, one real test email, SMS preview (simulated)
  • Roadmap slide: version comparison, multi-contract overview, real SMS

Checkpoints: CP1 at H4 · CP2 at H9 · CP3 at H13 · feature freeze at H16 · demo-safe at H21.5.

Disagreements the council settled

QuestionResolution
Who decides the page number?The server, from the verified quote's position in the text. All reviewers agreed.
Risk formulaAdditive capped points. Propagation starts from the state of the upstream obligation (not its score) and takes the maximum over paths, so risk never compounds.
Which links spread risk?Confirmed links plus AI-proposed links whose evidence checks out, with a "Reviewed links only" toggle. Reviewed-only by default would leave the demo graph empty.
Surviving a Render restartCache each Gemini call in Postgres, keyed by a hash of the model, prompt version, schema and input. After a restart, the job re-runs and finished batches are free cache hits. No heartbeat or lease machinery.
Gemini call budgetA token bucket set by the GEMINI_RPM environment variable, at most 2 calls at once, honouring Retry-After. Real limits are read off the quota page at H0.
Event namingA fixed list of event types plus other with a label; other events never merge automatically. Synonym merging was rejected because a wrong merge produces cascading wrong dates.

§3Architecture

A single FastAPI process runs the pipeline as an in-process asyncio task. Everything after extraction is a pure function of the database, so a review edit recomputes dates, graph and risk in under 100 ms without calling the LLM.

1IngestSize, magic bytes, page cap, encryption check; invisible-text filter; character-offset map
2SegmentHeadings from regex, bold and font size; header/footer strip; paragraph fallback; parties
3P1 extract~8k-char batches of whole clauses; flat schema; cached per call
4Verify + dedupeMatch quote to text, derive page; assign IDs; dedupe
5DatesResolve only from events that have a known date
6EdgesRule edges first, then P2 proposals; validate; break cycles
7ConflictsDeterministic comparison of attributes
8RiskComputed when read; recomputed on every change
Deterministic server codeGemini call (structured output, cached)
VercelReact + Vite + Tailwind · @xyflow/react + dagre · TanStack Query. The landing page pings /api/health to wake Render.
Render (1 worker)FastAPI · PyMuPDF · Pydantic v2 · google-genai · rapidfuzz · python-dateutil. CORS locked to the Vercel origin.
Neon PostgresSQLModel create_all plus scripts/seed_demo.py. No migrations: a schema change means drop and re-seed.
GeminiThe current Flash-class model, response_schema with a flat nullable schema, temperature 0, 45 s timeout.

Job lifecycle

  • POST /api/contracts hashes the PDF. If (sha256, PIPELINE_VERSION) is already analysed, it returns that analysis labelled "Cached analysis". Otherwise it starts a job and returns 202.
  • Each stage updates jobs.stage / progress_pct / message / updated_at. The UI polls every 1.5 s and shows a stage stepper with any warnings.
  • On startup, a job stuck in running for more than 2 minutes is claimed with an atomic UPDATE … RETURNING and re-run. Cached LLM calls make the re-run cheap.
  • PyMuPDF work runs in asyncio.to_thread, at most 2 jobs run at once, and a top-level wrapper always records a final state.

§6Gemini prompts & schemas

Two passes. Schemas stay flat, with nullable fields and enums instead of unions, because large nested schemas are a known cause of 400/500 errors from structured output.

Call budget and repair ladder

  • Pack whole clauses into batches of about 8k characters. An 8-page contract needs about 3 P1 calls plus 1 P2 call. Batch size is a config value, tuned by the eval at H8.
  • Ladder: response_schema → item-level Pydantic validation, keeping valid items → on a MAX_TOKENS finish, split the batch once → one re-ask with the validator error → otherwise mark the clauses extraction_failed and finish the job as done_with_warnings.
  • P2 takes at most 80 obligations and returns at most min(3N, 150) edges. If P2 fails, rule edges alone still give a real, evidence-backed chain.

§7Evidence & page references

A quote only counts once it is found in the actual PDF text. Its location there determines the page.

  1. Invisible-text filter at ingest. Drop spans with render mode 3, text colour matching the background, font size under 4 pt, or a bbox outside the page. This closes the hidden-text injection route.
  2. Normalize both sides: NFKC, ligatures such as ﬁ→fi, curly→straight quotes and dashes, soft hyphens removed, -\n joined, whitespace collapsed. Keep an index map back to the raw offsets.
  3. Match: quotes under 20 characters are rejected. Try an exact substring first, then rapidfuzz partial_ratio_alignment, accepting ≥ 92 (≥ 95 for 20–39 characters). Search the obligation's own clause first, then a ±1 page window, then the whole document.
  4. Uniqueness: if the quote matches more than one place, as boilerplate often does, it is unverified. Conan never guesses.
  5. Page = page_of(match_start), shown as "pp. 5–6" when the match crosses a page break.
  6. Unverified → confidence capped at 0.4, sent to Needs review, +10 risk. The page shows as "approx." with the clause's first page.

§8Dates & trigger events

A relative deadline stays unresolved until its trigger event has a date. Setting one event date resolves every obligation that depends on it, which is the demo moment where one click fills the timeline.

// obligations.deadline_rule (JSONB)
{ "kind": "relative",            // absolute|relative|recurring|none
  "raw_text": "within thirty (30) days of receipt of a valid invoice",
  "absolute_date": null,          // only if the literal date string is in the verified quote
  "offset": {"value":30,"unit":"day","day_type":"calendar"},
  "direction": "after",
  "anchor_event": "invoice_receipt",
  "recurrence": null,
  "is_conditional": false }

Resolution states

  • resolved: has a due date, provenance and trace
  • unresolved_trigger: waiting on an event date (shown in the "Needs trigger date" timeline lane)
  • conditional_pending: never counts as overdue
  • no_deadline · ambiguous

Example trace: invoice_receipt (2026-10-03, user-set) + 30 calendar days → 2026-11-02

  • Completion cascade: marking "Supplier delivers Goods" done on 1 Oct sets delivery = 2026-10-01 with source completion. That resolves "inspect within 5 business days of delivery", and so on down the chain.
  • Arithmetic: relativedelta handles months with month-end clamping. Business days skip Saturday and Sunday only; the trace says "holidays not considered". An unspecified day type is treated as calendar days, stated in the trace, with +5 risk.
  • Invariant: every non-null due_date has date_provenance ∈ {contract_text, user_event, completion}. A property test runs over every output.

Modifiers

  • Conditional pending: time factors count as 0
  • may / must_not: time factors × 0.5
  • done / waived / rejected: score 0 and never propagate

Propagation (D1)

Sources are obligations that are blocked or overdue (s = 1.0) or have an unresolved date (s = 0.5). Walking downstream, each path contributes

30 × s × Π w(edge) × 0.6^(hop−1)      hop ≤ 3
w: condition_for 1.0 · depends_on 1.0 · must_precede 0.8 · may_trigger 0.6
node impact = max over all paths (never a sum), capped at 30

It uses the source's state, not its score, so risk never compounds and adding an unrelated obligation changes nothing else. Eligible edges are confirmed ones plus proposed ones with verified evidence. Unverified or rejected edges never propagate.

§10Potential conflicts (D2)

About two hours of work, deterministic first. Conan flags inconsistencies and never decides which clause prevails.

  • Group obligations by (actor, counterparty, category, trigger_event, action stem) using a small stem map: pay / paid / payment → pay.
  • Flag a pair when offsets differ (weeks converted to days), day types differ (neither unspecified), amounts differ by more than 1%, or absolute dates differ.
  • Notice periods: a regex pulls "N days' (prior) (written) notice" out of termination and renewal clauses and compares them.
  • LLM layer (flag ENABLE_LLM_CONFLICTS, optional): optional potential_conflicts in the P2 schema. An item is kept only if both quotes verify. There are never per-pair calls.
  • Copy: "§6.3 (p. 4) sets payment within 30 days of invoice receipt; Schedule B (p. 9) states Net 45. These may be inconsistent. Conan does not determine which prevails; check the order-of-precedence clause or ask counsel."

§14Testing & eval

Unit tests (replay mode, no network)

  • Segmentation page spans; header/footer strip; invisible-span filter
  • Verifier: exact, whitespace drift, ligatures, curly quotes, hyphenation, cross-page, duplicate quote → unverified, fabricated → fail, short → fail
  • Dates: weekends, month-end, leap year, unspecified day type, unresolved stays null, completion cascade
  • Edges: bad IDs, self-loops, cycles, unverified edges never propagate
  • Risk: snapshot at a fixed as_of; diamond graph does not saturate; adding an unrelated obligation changes nothing else; band boundaries 24/25 and 49/50
  • Injection fixture: no unverified item survives, and risk is unchanged

Invariants and eval

  • Property test: every non-null due date has valid provenance
  • Property test: every verified obligation's page contains its quote
  • eval_score.py on the gold set. A prediction matches when the evidence span's character IoU is ≥ 0.5, or when clause and actor match and action/object token Jaccard is ≥ 0.5. It reports precision, recall ≥ 0.80, per-field accuracy, page accuracy and invented dates (must be 0).
  • A live smoke run after every prompt change, because replay mode hides 429s; plus a forced-429 test with a fake client
  • Frontend: a 12-step manual checklist and an unaided test by someone new at H19–21

Security & boundaries

  • Keys live only in Render's environment; CORS is locked to Vercel; nothing secret goes into the frontend bundle.
  • Uploads: size ≤ 10 MB checked while streaming, %PDF- magic bytes, page count ≤ 30 checked before a full parse, a 20 s parse timeout, and a sanitized filename.
  • Logs contain only job IDs, stages, counts and codes, never contract text, quotes or prompts. SDK debug logging is off.
  • Injection defence: invisible text is filtered, content goes inside delimited tags, schemas are strict with length caps, IDs and pages are assigned by the server, and quotes are verified. The UI also shows a "clauses with no obligations" count so an omission is visible.
  • React escapes all output: no dangerouslySetInnerHTML, and LLM text is never rendered as Markdown. ICS text is CRLF-escaped.
  • The test email is not an open relay: one recipient, the address typed in, max 3 per hour per IP. /sample is idempotent.
  • A disclaimer banner states that Conan is not legal advice, never decides which clause prevails, and should only be used with fictional or public contracts, because free-tier Gemini inputs may be used by Google.

§16Decision record

Rejected

  • Page numbers from the LLM (printed labels ≠ physical pages; loose matching passes boilerplate)
  • Weighted-average risk (hides severe single factors) and summed propagation (turns the graph red)
  • One LLM call per clause or per pair (impossible on free-tier RPM)
  • LLM-based segmentation (breaks character offsets)
  • Heartbeat/lease/resume machinery (replaced by memoization)
  • Synonym merging of events (replaced by a fixed list)
  • Queue services such as Redis or Celery; real Twilio SMS; reminders through public webhooks

Open risks

  • Actual Gemini free-tier limits and model behaviour (verify at H0)
  • Segmentation on messy CUAD layouts (paragraph fallback; the demo contract is controlled)
  • Person A's workload (B takes over modules if CP2 slips)
  • Recall ≥ 80% on the first prompt: about 60% confidence (eval loop at H16–19)

Conditions before code

  1. Confirm the Gemini model, quota and flat-schema behaviour at H0
  2. Hello-world deploys live on all three hosts
  3. API contract, TS types and fixture committed before parallel work starts
  4. Fictional or public contracts only
  5. External post-implementation review at freeze
